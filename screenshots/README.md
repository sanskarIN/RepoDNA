## How they were made

- **The interface** of each version was built from the code at its tag.
- **The analysis** was made by the command line of the same version. For 1.0.0, 1.1.0,
  and 1.1.1, that is the Linux build downloaded from the GitHub release and checked
  against its `SHA256SUMS.txt`. It analyzed a checkout of this repository at the tag,
  with only the branches and tags that existed then, and with `--reproducible` and
  `SOURCE_DATE_EPOCH` set to the moment the release was published. The 1.2.0 analysis
  was made on the day of that release, and so were the 1.2.1 and 1.2.2 analyses, with
  `--reproducible`: for 1.2.1 of a checkout at its tag, and for 1.2.2 at `2dbdaa6`, the
  last commit on `main` before the changes that made 1.2.2. The 1.3.0 analysis is of
  `13f8c8a`, the last commit of 1.3.0 before its screenshots were added, and the 1.3.1
  analysis of `a73f314`, the same for 1.3.1, both with `--reproducible` and
  `SOURCE_DATE_EPOCH` set to the time of that commit.
- **The screenshots** were taken in Chromium: desktop views in a 1440 × 810 window at twice
  the resolution (the module map in a 1680 × 945 window, so that every module fits), and
  phone views on a 390 × 844 screen at three times the resolution. They were rendered
  with the Inter and JetBrains Mono fonts; the interface itself uses the system font of
  the computer it runs on.
- **The desktop app** of 1.2.0 was built from its tag, that of 1.2.1 from the commit
  after its tag, whose only change does not show in these views, and those of 1.2.2,
  1.3.0, and 1.3.1 from the code of their releases. Each was shown in its
  default 1320 × 860 window at twice the scale, with an analysis of this repository
  stored on that machine and the same fonts.

1.3.0 adds a screenshot of the start page, with the analysis it opened listed under
Recent analyses. In 1.3.1, the web interface was built with its WebAssembly analysis, so
the start page also shows analyzing a repository in the browser.

Screenshots of a new release go in a folder named after its tag, such as `v1.4.0`, with
the same views, and a column and a section on this page.
