# RepoDNA v1.4.3 release qualification

This is the sign-off checklist for the **next stable release**. This file tracks
requirements; its presence does not mean those requirements have been met.

## Source and integration

- [ ] Merge v1.4.3-scope PRs only after CI and CodeQL pass.
- [ ] Resolve merge conflicts against `main`, rerun checks on rebased heads, and
  verify no unwanted changes were lost.
- [ ] Confirm the final v1.4.3 changelog includes only work actually merged.
- [ ] Confirm the exact support links, including
  `https://razorpay.me/@SanskarCodes`, are preserved.

## Release metadata

- [ ] `npm ci` and `npm run release:check` pass with v1.4.3 on the final branch.
- [ ] `cargo test --locked --workspace` and the desktop locked build pass.
- [ ] The root, web, desktop, schema, visualization, and wasm npm manifests, the
  npm lockfile, the Rust workspace and desktop manifests, both Rust lockfiles,
  and the Tauri configuration all agree on **1.4.3**.
- [ ] `CHANGELOG.md` has a final, dated `[1.4.3]` entry.

## Behavior and privacy

- [ ] Check browser-only analysis works offline after the first successful load,
  without uploading source files.
- [ ] Verify the local server and desktop can open reports and analysis artifacts.
- [ ] Verify recent-analysis retention preferences, malformed-data handling,
  worker startup failures and progress reporting.
- [ ] Verify filtered Findings CSV downloads correctly, escapes spreadsheet
  formulas, and works in the desktop save-dialog flow if its feature PR is merged.
- [ ] Verify the Files explorer's file-state filters and exported file tables.
- [ ] On Windows x64 and ARM64, verify the initial desktop window is centered and
  does not cover the taskbar on normal or scaled laptop displays. It must remain
  resizable, and the sidebar must remain usable at compact sizes.
- [ ] On the first launch after installing v1.4.3, verify that **What's New**
  appears with highlights for 1.4.3 (not Unreleased or an older release).
- [ ] Dismiss **What's New**, restart RepoDNA and confirm it does not reappear
  during that version; reopen it manually from App > What's New.
- [ ] Verify that a future version update will show the announcement again
  without uploading data or requiring an internet connection.
- [ ] Record the maintainer's explicit approval before creating the stable
  `v1.4.3` tag. An unpublished Windows review build is not approval.

## Binary and package validation

- [ ] Run `Release` via **Actions > Release > Run workflow** on the final
  v1.4.3 commit with the `tag` input left **empty**. This is an unpublished trial.
- [ ] Verify the trial's Linux/macOS CLI archives, Windows x64/Arm64 portable ZIPs,
  desktop packages, WebAssembly binary and web distribution were built.
- [ ] Verify both Windows desktop MSI and setup EXE assets on x64 and Arm64,
  plus the WinGet manifest ZIP. Confirm all expected files are nonempty.
- [ ] Check package staging and dependency/security audits pass before any
  npm or container publishing step.
- [ ] Confirm the checksums and release inventory correspond to the final files.
- [ ] Do not claim WinGet availability until Microsoft has indexed the packages.

## Final publication

- [ ] Require successful CI, CodeQL, and unpublished trial for the exact release commit.
- [ ] Merge the v1.4.3 preparation PR after all checks pass.
- [ ] Tag that verified `main` commit `v1.4.3`; never tag an outdated branch head.
- [ ] Verify the tag-triggered Release workflow and public GitHub release assets.
- [ ] Check external npm/container registries before announcing availability.
- [ ] Keep the release tagged stable only if validation and publication complete.

**No stable tag or publication is authorized merely by checking in this document.**
