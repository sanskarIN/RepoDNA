## Manual CLI functional QA evidence (recorded 2026-11-16)

The pre-checklist-update trial at [run #43805700070](https://github.com/sanskarIN/RepoDNA/actions/runs/43805700070), source SHA `0298062406b1665c84171f812e554d206bc72060`, produced the x86_64 Linux musl CLI reporting `repodna 1.5.1`. The checks were carried out with an isolated temporary HOME/XDG directory and synthetic repositories and URLs, with details also recorded in [PR #276](https://github.com/sanskarIN/RepoDNA/pull/276).

- A saved scan survived `cache reset --yes` byte-for-byte as an unindexed JSON artifact, then `cache repair` re-indexed it and restored its listing.
- An additional orphan artifact caused `clean --all --yes` to refuse destructive cleanup with exit code 3, preserving both saved artifacts.
- Importing arrays where required objects belong (`tool`, `identity`, `structure`, `git`, `analysisMetadata`) failed schema validation without storing malformed content.
- Synthetic HTTPS credentials in a Git remote were not printed to stdout or stderr after a controlled DNS failure.
- Mixed-radix loopback aliases (`0177.0.0.1`, `0x7f.0x0.0x0.0x1`) and special-use remote IP literals were rejected before a connection attempt; documented private-host opt-in reached a deliberately closed local port.

**Exact-SHA caveat:** this evidence tested the executable produced from the SHA above. Any later candidate commit, including a documentation-only checklist synchronization, requires the full CI/CodeQL/release-trial runs again, and the new trial's inventory and checksums must be reverified before release. Do not cite the older trial as an exact-SHA build of a later commit.
