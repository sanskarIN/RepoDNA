## Additional security advisory during final qualification — 2026-11-24

The current exact-head [CI desktop advisory job](https://github.com/sanskarIN/RepoDNA/actions/runs/45357019808)
reported **RUSTSEC-2026-0594**, because transitive `cookie` 0.18.2 was
locked through Tauri. The fix updates the **desktop Cargo.lock only**
to `cookie` 0.18.3, using the non-yanked version and SHA-256 checksum from
the authoritative [crates.io index](https://github.com/rust-lang/crates.io-index/blob/master/co/ok/cookie).
The resolved nonoptional dependency set remains exactly `time` and
`version_check`; no new package requirements or app source changes were
introduced. The root Cargo.lock has no `cookie` crate.

- [x] Replace transitive `cookie` 0.18.2 with 0.18.3 without disabling the
  blocking desktop advisory job.
- [x] Preserve only the existing `time` and `version_check` dependencies
  as verified against the crate index, retaining their original lockfile
  versions.
- [x] Record both RustSec fixes in dated changelog notes and add a regression
  assertion for the patched desktop lockfile entry/checksum.
- [ ] Re-run exact-new-SHA CI, CodeQL and full unpublished Release trial;
  **previously qualified candidate SHA and artifacts are superseded**.
- [ ] Verify both dependency audits, the native Windows CLI smoke matrix,
  four MSI/NSIS installer checks, and all 15 release SHA-256 assets.
- [ ] Real Windows x64/ARM64 GUI installation, upgrade, local-data checks,
  and the owner's exact-SHA release approval remain required.

The vulnerable crate in a lockfile does not by itself prove application-level
exploitability. Keep the issue open for additional reachability analysis;
do not misrepresent the dependency fix as proof of a reachable flaw.
