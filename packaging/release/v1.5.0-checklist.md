# RepoDNA v1.5.0 — development and stable-release qualification

**Status: development only (not release-ready).** The latest published stable
version is **v1.4.5** (2026-10-30). No v1.5.0 tag, release, or new installed
version is authorized by this document. Keep version metadata at 1.4.5 until
the final release-candidate freeze.

The goal is a **review-ready repository impact workflow** with safer local
Findings exports, not a version-number-only release. Each feature must have its
own testable PR, backward-compatibility review, and evidence for its claims.

- [ ] Document complete examples for end-users. Clearly distinguish available

## Native AI evidence and privacy

- [ ] Preserve offline, opt-in native extractive explanations; an optional
  locally trained ranker is **not** a generative language model.
- [ ] Keep all model checkpoints local by default; do not add automatic
  downloads, telemetry, API-key requirements or code uploads.
- [ ] Re-run deterministic training/replay, checkpoint size and regular-file
  limits, repository-disjoint split validation and provenance checks.
- [ ] Include synthetic benchmarks only as pipeline regression fixtures.
  **Never** claim production relevance, citation correctness, generative
  capability or factual accuracy from them.
- [ ] Track independent benchmark review work in
  [#173](https://github.com/sanskarIN/RepoDNA/issues/173): license/source
  checks, non-overlapping repository families, independent adjudication,
  validation/test separation, and human citation-grounding assessment before
  making measured quality claims.
- [ ] Verify that privacy-preserving exports describe precisely what is and
  is not redacted. Confirm local-only output even with untrusted filenames,
  commit subjects or evidence.

  Rust and desktop groups; never bulk-merge conflicting lockfile changes.

  `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo test --workspace --locked`,
  `npm ci`, `npm run format:check`, `npm run typecheck`,
  `npm test`, and `npm run build`.

## Version freeze, dry run and publication

- [ ] Freeze reviewed features and record the **exact commit SHA**. No open
  blockers or unresolved security issues.
- [ ] In a release-candidate branch, synchronize **1.5.0** across Rust workspace
  crates, the desktop Tauri manifest, both Cargo lockfiles, every npm workspace,
  `package-lock.json`, generated metadata and installation examples.
- [ ] Add a dated `[1.5.0]` changelog entry containing only merged changes.
  Update tested What's New highlights and documentation; check support URLs
  including exactly `https://razorpay.me/@SanskarCodes`.
- [ ] Pass `npm run release:check`, `npm run links:check` and applicable
  release script tests on the frozen version metadata.
- [ ] Run the Release GitHub Actions workflow with an **empty tag** on that
  exact candidate branch. Confirm `publish=false` and inspect every job,
  produced installer, archive, checksum and trial artifact. A passing CI
  workflow alone does not prove release quality.
- [ ] Obtain maintainer approval **after** trial verification; only then
  create the `v1.5.0` tag and publish the stable GitHub release.
- [ ] After publishing, independently confirm the downloadable assets and
  version metadata, and separately verify package-manager indexing before
  advertising winget/npm/container availability.
