# RepoDNA v1.5.0 — development and stable-release qualification

**Status: v1.5.0 stable published on November 6, 2026.**
[GitHub Release](https://github.com/sanskarIN/RepoDNA/releases/tag/v1.5.0)
contains 15 platform/distribution assets plus `SHA256SUMS.txt` (16 files).
The approved, immutable tag points to
`6d2014ed48682b9d238ba22f3c1dcd8ccb90b47c`.
The exact source tree matches the qualified unpublished candidate.
The [published Release workflow](https://github.com/sanskarIN/RepoDNA/actions/runs/42157288265)
succeeded. Unchecked items below remain manual QA or future-development
follow-ups; they are not claims that those items passed.

The goal is a **review-ready repository impact workflow** with safer local
Findings exports, not a version-number-only release. Each feature must have its
own testable PR, backward-compatibility review, and evidence for its claims.

## Native AI evidence and privacy

- [ ] Preserve offline, opt-in native extractive explanations; an optional
  locally trained ranker is **not** a generative language model.
- [ ] Keep all model checkpoints local by default; do not add automatic
  downloads, telemetry, API-key requirements or code uploads.
- [ ] Re-run deterministic training/replay, checkpoint size and regular-file
  limits, repository-disjoint split validation and provenance checks.
- [ ] Include synthetic benchmarks only as pipeline regression fixtures.
  **Never** claim production relevance, citation correctness, generative
  capability or factual accuracy from them.
- [ ] Track independent benchmark review work in
  [#173](https://github.com/sanskarIN/RepoDNA/issues/173): license/source
  checks, non-overlapping repository families, independent adjudication,
  validation/test separation, and human citation-grounding assessment before
  making measured quality claims.
- [ ] Verify that privacy-preserving exports describe precisely what is and
  is not redacted. Confirm local-only output even with untrusted filenames,
  commit subjects or evidence.
