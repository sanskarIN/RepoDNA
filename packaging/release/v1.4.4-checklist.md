# RepoDNA v1.4.4 release qualification

This checklist tracks the remaining work for a **candidate** v1.4.4 maintenance
release. A checked-in checklist does not authorize a tag or publication.

## Integration and regression coverage

- [ ] Merge reviewed PRs only after their exact head commits pass CI and CodeQL.
- [ ] Integrate browser folder path safety (PR #114), recent-analysis storage recovery
  (PR #115), and local API response validation (PR #116), or document any change
  deferred from v1.4.4.
- [ ] Close duplicate older PRs only once their replacement is merged and verified.
- [ ] Recheck `main` after merges, especially files touched by parallel branches.
- [ ] Verify the v1.4.3 stable release remains untouched while v1.4.4 is developed.

## Behavior and privacy

- [ ] Browser folder selection refuses traversal, unsafe paths, duplicated filenames,
  and mixed repository roots without uploading any source data.
- [ ] Normal folder selections and dropped folder traversal still work, including
  nested directories and .gitignore exclusions.
- [ ] Corrupt saved recent-analysis metadata never prevents valid analyses from
  loading, and existing user retention preferences still apply.
- [ ] Local API error cases produce explicit user-facing failures without exposing
  session tokens, while normal repository, scan and DNA-card views still render.
- [ ] Validate filtered Findings CSV and JSON exports, both with complete matching
  rows; JSON must preserve evidence and CSV must remain spreadsheet-safe.
- [ ] Confirm the first-launch What's New notification is shown once for 1.4.4
  and the full changelog is accessible offline from the sidebar.
- [ ] Recheck the Windows default window size, resizability and sidebar at common
  DPI scaling levels on laptop displays.

## Quality and dependencies

- [ ] `npm ci`, `npm run format:check`, `npm run typecheck`, `npm test`, and
  `npm run build` pass on the release candidate.
- [ ] `cargo test --locked --workspace` and desktop locked builds pass.
- [ ] Both Rust lockfiles pass `cargo deny check advisories`, plus license, source
  and dependency ban checks. Resolve or explicitly document issue #59.
- [ ] Verify optional AI HTTPS/certificate trust smoke behavior if enabled.
- [ ] Rust, WebAssembly, Windows/macOS/Linux desktop, Action, and CodeQL checks
  pass against the same exact release commit.

## Packaging and publishing

- [ ] Synchronize version **1.4.4** across npm workspace packages, lockfiles,
  Rust crates, Tauri metadata, and generated artifacts.
- [ ] Finalize and date the 1.4.4 changelog, containing only merged behavior.
- [ ] Run `npm run release:check` and the support-link audit; retain the
  official Razorpay URL `https://razorpay.me/@SanskarCodes`.
- [ ] Run the Release workflow with an **empty tag** for an unpublished trial.
- [ ] Smoke-test portable CLI ZIPs and desktop MSI/EXE installers on supported
  Windows architectures, plus Linux/macOS archives and WebAssembly artifacts.
- [ ] Verify installer and WinGet manifest inventory, archive safety, nonempty
  assets, SHA-256 checksums, npm staging and container publish gates.
- [ ] Confirm WinGet availability independently before advertising installation
  commands for the Microsoft catalog.
- [ ] Publish the stable tag **only after** successful final CI, release-trial
  validation, and explicit maintainer approval.

**Status: development only. No v1.4.4 tag, pre-release, or stable publication
is implied by this file.**
